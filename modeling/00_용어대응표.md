## 1. ER 모델 구성요소
| 용어 | 뜻 (PPT 기준) |
|---|---|
| 엔티티 (Entity) | 실존(고객, 상품, 직원)하거나 개념적인 것(주문, 결제). 테이블. 인스턴스 2개 이상, 속성 2개 이상이어야 함 |
| 인스턴스 | 엔티티의 한 건. 행(row) |
| 관계 (Relationship) | 엔티티 간의 규칙과 관계 |
| 속성 (Attribute) | 데이터를 표현하는 최소 단위. 컬럼 |
| 식별자 (Identifier) | 인스턴스를 구별할 수 있는 속성. 기본 키 |
| ER 모델의 질적 특성 | 완전성, 정확성, 최소성, 자명성, 확장성, 표현성, 가독성 |

## 2. 엔티티
| 용어 | 뜻 |
|---|---|
| 핵심 엔티티 (기준정보) | 단독으로 존재. 업무 행위의 주체·대상. 4가지: **유형 및 분류**(고객 유형 코드, 상품 분류 대중소), 업무규칙 및 지식, 업무주체 및 대상, 장소 |
| 파생 엔티티 | 핵심 엔티티와 관련된 엔티티: **상세, 상태, 이력, 교차** |
| 엔티티 분류 | 주로 엔티티 형태, 엔티티 생성 관점의 분류를 사용 (PPT의 세부 표는 이미지라 텍스트로 확인하지 못함) |
| 일반화 / 특수화 | 일반화: 개인 고객, 법인 고객의 공통 속성을 고객 엔티티로 통합 / 특수화: 각각 개별 속성만 포함 |

## 3. 관계
| 용어 | 뜻 |
|---|---|
| 관계수 (cardinality) | 두 엔티티 간에 대응되는 행의 개수: 1:1, 1:M(1:n), M:N |
| M:N 해소 | 학생 M:N 과목 → 학생 1:n **학생_수강과목** n:1 과목 (PPT 예시) |
| 선택성 (optionality) | 관련 행의 존재가 필수(\|) 또는 선택(O): 필수-선택, 필수-필수, 선택-선택 |
| 식별자 상속 | 한 엔티티의 식별자(PK)가 다른 엔티티로 넘어가는 것 |
| 식별 관계 | 상속된 식별자가 자식의 **PK가 되는** 경우 (주문 → 주문 상세: 주문번호(PK, FK) + 일련번호(PK)) |
| 비식별 관계 | 상속된 식별자가 자식의 **PK가 되지 않는** 경우 (고객 → 주문: 고객번호(FK)) |
| 관계 유형 | **기본 관계, 재귀적 관계, 병렬 관계, 슈퍼타입/서브타입 관계** |
| 관계 정의 | 종속관계, 참조관계. 주체, 대상, 상세, 인과, 역할/자격, 구성, 참조 관계로 구분. 양방향으로 관계수, 선택성, 식별자 상속을 정의 |

## 4. 속성
| 용어 | 뜻 |
|---|---|
| 속성 정의 항목 | 속성명(표준 단어 조합), 식별자 여부, 옵셔널리티(필수/선택), 도메인(타입과 범위) |
| 단순 속성 / 복합 속성 | 더 나눌 수 없는 속성 / 여러 요소로 나뉘는 속성 (주소) |
| 저장 속성 / 파생 속성 | 직접 저장하는 속성 / 다른 값으로 계산할 수 있는 속성 |
| 단일 값 속성 / 다중 속성 | 값이 하나 / 값이 여러 개 (1정규형 위반 → 분리 대상) |
| 도메인 | 속성 값의 타입과 범위 (예: 학년, 숫자, 1~4) |

## 5. 식별자와 키
| 용어 | 뜻 |
|---|---|
| 식별자의 특성 | **유일성, 최소성, 불변성, 존재성** |
| 본질 식별자 / 인조 식별자 | 업무에 원래 있는 값 / 시스템이 만든 값 |
| 인조 식별자를 쓰는 경우 | ① 엔티티 통합 시 공통 식별자가 없을 때 ② 복합키를 단순히 할 때 ③ 개인정보 암호화 대상일 때 ④ 업무상 편의 |
| 주 식별자 / 대체 식별자 | 대표로 쓰는 식별자 / 그 외의 식별자 |
| 기본 키 (PK) | 테이블 내 한 행을 식별해 주는 컬럼 |
| 참조 키 (FK) | 다른 테이블에서 참조하는 컬럼 (외래키) |
| 후보키 / 대체키 / 수퍼키 | 기본키로 쓸 수 있는 키 / 기본키는 아니지만 대신 쓸 수 있는 키 / 키로 쓸 수 있는 모든 키(최소성 불필요) |

## 6. 제약 조건과 정규화
| 용어 | 뜻 |
|---|---|
| 키 제약조건 | PK 중복 확인 |
| 실체 무결성 | 반드시 값이 존재하는지 (NOT NULL) |
| 영역 무결성 | 값의 타입과 범위 확인 |
| 참조 무결성 | FK가 참조하는 값이 존재하는지 |
| 함수 종속 | 완전 함수종속, 부분 함수종속, 이행적 함수종속 |
| 정규화 | 1정규형(원자성), 2정규형(부분 종속 해소), 3정규형(이행 종속 해소) |
| 역정규화 | 조회 성능을 위해 정규화 이전으로 되돌리는 것 |

## 7. 이력 관리 방법
- 속성 전체 이력 vs 속성 일부 이력
- **점 이력 vs 선분 이력**
- 최종 데이터 포함 vs 미포함

## 8. 데이터 모델링 절차 (핵심 데이터 모델링 p.70 기준)
| 단계 | 하는 일 |
|---|---|
| 분석 | 업무 분석(AS-IS), 방향 수립(TO-BE), 데이터 분석, 요구 정의 |
| 개념 모델링 | ① 주제영역 도출 ② 주제영역 분류 및 정의 ③ 핵심 엔티티 정의 및 관계 정의 (+ 식별자와 주요 속성 먼저 정의) |
| 논리 모델링 | 엔티티 도출 및 식별 → 엔티티 정의 → 엔티티 통합(일반화/특수화) → 데이터 통합 → 관계 도출 및 정의 → 속성 도출 및 정의 → 식별자 지정 → 도메인 및 데이터타입 지정 → 데이터 모델 검토 |
| 데이터 표준화 | 표준 단어, 표준 용어, 표준 도메인, 표준 코드 (영문 약어 명명 기준) |
| 물리 모델링 | 테이블 설계, 관계 설계, 컬럼 설계, 무결성 설계, 인덱스 설계, 성능을 고려한 데이터 구조 |

### 물리 모델링 세부
| 항목 | 내용 |
|---|---|
| 테이블 설계 | 슈퍼타입 기준 / 서브타입 기준 / 슈퍼타입·서브타입 테이블 설계 |
| 관계 설계 | **기본적인 관계**(참조키), **상호배타적 관계**(참조 컬럼 통합 또는 분리), **재귀적 관계**(계층 관계 표현) |
| 컬럼 설계 | 속성과 컬럼 1:1 변환. **테이블 마지막에 시스템 컬럼 4개** 추가. CHAR vs VARCHAR, DATE vs VARCHAR(8), VARCHAR vs NVARCHAR |
| 성능 고려 | 집계/요약 테이블, 역정규화, 중복 컬럼 추가, 테이블 분할(**수직, 수평**) |

## 9. PPT에 없는 용어 (PPT 외)
| 용어 | 비슷한 PPT 용어 |
|---|---|
| 인접 목록 (Adjacency List) | 재귀적 관계 |
| 경로 열거, 중첩 집합, 클로저 테이블 | 없음 (계층 저장 방식의 실무 기법) |
| 조건부 유일 | 없음 |
| 스냅샷 | 없음 (주문 시점 값 복사) |
| PII 분리, 암호화 + 해시 검색 | 없음 (인조 식별자 사용 이유 ③과 관련) |
