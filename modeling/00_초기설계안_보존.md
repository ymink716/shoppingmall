# 패션 쇼핑몰 DB 설계안 (상세 컬럼 버전)

## Context
빈 디렉터리(/Users/ymink/claude)에서 새 **패션 쇼핑몰**을 시작하려 함. 단일 판매자 B2C 기준, 실서비스 수준의 컬럼까지 정의한다.
패션 도메인 특성 반영: 색상×사이즈 옵션, 색상별 이미지, 사이즈 실측표, 모델 착용 정보, 소재·세탁 정보, 리뷰의 체형/사이즈 핏, 사이즈 교환, 재입고 알림, 코디(룩북).
가정: **Oracle 19c**(12c 이상이면 동일, 23ai는 BOOLEAN/JSON 네이티브 타입 사용 가능), 원화 결제(금액은 `NUMBER(19)` 원 단위), 상품 옵션(SKU) 있음, 쿠폰·적립금 포함.
모든 테이블 공통: `created_at TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL`, `updated_at TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL` (아래 표에서는 생략).

## Oracle 적용 규칙 (Oracle 19c 기준, 23ai면 일부 네이티브 타입 사용 가능)
| 용도 | Oracle 타입 | 비고 |
|---|---|---|
| PK | `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY` | 12c+. 11g 이하면 SEQUENCE + 트리거/`seq.NEXTVAL` |
| 정수/금액 | `NUMBER(19)` / `NUMBER(10)` / `NUMBER(5)` | 금액은 원 단위 정수 |
| 소수 | `NUMBER(p,s)` | 평점, 적립률, 실측 cm |
| 문자열 | `VARCHAR2(n CHAR)` | **CHAR 시맨틱 필수** — 기본 BYTE면 AL32UTF8에서 한글 1자=3바이트라 VARCHAR2(50)에 한글 16자밖에 안 들어감 (또는 `NLS_LENGTH_SEMANTICS=CHAR` 설정) |
| 긴 텍스트 | `CLOB` | 상품 상세, 리뷰 본문 |
| 여부(Y/N) | `CHAR(1) DEFAULT 'N' NOT NULL CHECK (col IN ('Y','N'))` | 19c엔 CHAR(1) Y/N 컬럼 없음(23ai부터 지원) |
| 일시 | `TIMESTAMP` (서버 KST 단일이면) / `TIMESTAMP WITH TIME ZONE` (해외 대비) | `DEFAULT SYSTIMESTAMP` |
| 날짜만 | `DATE` | 생년월일 (Oracle DATE는 시분초 포함 주의) |
| JSON | `CLOB CHECK (col IS JSON)` | 23ai면 `JSON` 타입 |
| UUID | `RAW(16)` (`SYS_GUID()`) 또는 `VARCHAR2(36)` | |
| IP | `VARCHAR2(45)` | IPv6 대비 |
| enum 상태값 | `VARCHAR2(20)` + `CHECK (status IN (...))` | 또는 공통코드 테이블 |

**Oracle에서 특히 주의할 점**
- **빈 문자열('') = NULL**: `NOT NULL` 컬럼에 '' 저장 시 에러. 앱에서 빈 값 처리 규칙 통일.
- **예약어 회피**: `USER`, `UID`, `SIZE`, `LEVEL`, `COMMENT`, `ORDER`, `NUMBER`, `DATE`, `ACCESS`, `MODE` 등은 컬럼/테이블명 금지 → 본 설계는 `user_id`, `size_id`, `orders`, `tracking_no` 등으로 이미 회피.
- **식별자 길이**: 12.2 미만은 30바이트 제한 → 긴 이름(`marketing_reconfirmed_at` 등)은 OK지만 제약조건명 `FK_USER_TERMS_AGREEMENTS_TERMS` 같은 건 30자 넘지 않게 축약.
- **부분 UNIQUE(조건부)**: PostgreSQL의 `WHERE` 부분 인덱스가 없음 → 함수 기반 인덱스로 대체.
  예) 탈퇴 회원 제외 이메일 중복 방지: `CREATE UNIQUE INDEX UX_USERS_EMAIL ON users (CASE WHEN status <> 'WITHDRAWN' THEN email_hash END);`
  예) 기본 배송지 1개만: `CREATE UNIQUE INDEX UX_ADDR_DEFAULT ON user_addresses (CASE WHEN is_default='Y' THEN user_id END);`
- **updated_at 자동 갱신 없음**: 앱(JPA `@PreUpdate`/MyBatis)에서 세팅하거나 BEFORE UPDATE 트리거.
- **FK에 인덱스 자동 생성 안 됨**: FK 컬럼마다 인덱스 수동 생성(부모 삭제/조인 시 락·풀스캔 방지).
- **재고 차감**: `UPDATE ... WHERE id = :id AND stock_quantity >= :qty` 후 `SQL%ROWCOUNT` 확인, 또는 `SELECT ... FOR UPDATE NOWAIT`.
- **페이징**: 12c+ `OFFSET n ROWS FETCH NEXT m ROWS ONLY`, 대용량 목록은 키셋 페이징(`WHERE id < :lastId`).
- **암호화(🔒 컬럼)**: 앱 레벨 AES-256 또는 Oracle TDE(컬럼 암호화, Advanced Security 라이선스 필요) / DBMS_CRYPTO.
- **이력·로그성 테이블**(login_histories, stock_histories 등)은 월 단위 Range 파티셔닝 고려(Partitioning 옵션은 EE 유료).

## 설계 핵심 원칙 (패션 특화 포함)
0. **SKU = 상품 × 색상 × 사이즈**: 재고·장바구니·주문은 variant 기준, 이미지·모델컷은 색상 기준, 실측은 사이즈 기준으로 각자 맞는 단위에 붙인다.
0-1. **사이즈 정보가 반품률을 좌우**: size_charts + model_wearings + 리뷰 size_fit/체형 데이터로 상품 페이지에서 “구매자 72%가 정사이즈” 같은 정보를 제공 → 교환/반품 감소.
1. **스냅샷 저장**: 주문 시점의 상품명·옵션·가격·배송지·주문자 정보를 orders/order_items에 복사. 상품이 수정·삭제돼도 주문 내역 불변.
2. **재고는 SKU 단위 + 조건부 차감**: `UPDATE product_variants SET stock_quantity = stock_quantity - :qty WHERE id = :id AND stock_quantity >= :qty` → 영향받은 행 0이면 품절 처리. 변경 시 stock_histories 기록.
3. **금액은 정수(NUMBER(19), 원 단위)**, FLOAT 금지. 할인 금액은 주문·항목 양쪽에 저장해 부분 취소 시 환불액 계산 가능하게.
4. **상태 변경 이력 테이블**(order_status_histories, point_histories, stock_histories)로 CS·정산 추적.
5. **캐시 컬럼**(point_balance, rating_avg, review_count, sales_count)은 원본 이력 테이블에서 재계산 가능하도록 유지.
6. **Soft delete**: users, products, reviews는 deleted_at 사용(FK 이력 보존).
7. **인덱스**: orders(user_id, ordered_at DESC), orders(status), order_items(order_id), products(category_id, status), product_variants(product_id), user_coupons(user_id, status), point_histories(user_id, created_at), reviews(product_id, created_at).
