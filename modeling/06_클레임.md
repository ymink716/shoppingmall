# 6회차: 클레임(취소·교환·반품) 테이블 설계

> 무신사 기반 쇼핑몰 데이터 모델링 실습
> 진행 방식: ① 설계 유형 정리 → ② 테이블 설계 → ③ 컬럼 확인
> 용어는 수업 PPT를 참고합니다. PPT에 없는 실무 용어는 **(PPT 외)** 로 표시합니다.
> DBMS는 미정이므로 컬럼 타입은 도메인으로 표기합니다.

## 목차
0. 클레임은 어떤 엔티티인가
1. 클레임 설계 유형 (1~24)
2. 추천 조합
3. 테이블 설계 (논리 모델링 절차)
4. 컬럼 확인 포인트와 확정 결과
5. 업무 규칙과 다음 회차로 넘긴 항목

## 0. 클레임은 어떤 엔티티인가

- 클레임은 주문 이후에 고객·판매자가 **주문을 되돌리거나 바꾸는 행위**입니다. 취소(배송 전), 반품(배송 후 돌려보냄), 교환(배송 후 다른 옵션으로 바꿈)을 묶어 부릅니다 (PPT 외 용어).
- 앞 회차와의 관계 (이번 회차에서 받는 항목)
  - 4회차 확인 10번: 수량 일부 취소는 **클레임상품 수량**으로 처리, 주문상품 상태는 남은 수량 기준
  - 4회차: 부분 취소 시 배송비 재계산 (판매자 주문의 배송비 정책 스냅샷), 할인·적립금 배분 금액의 수량 비례 회수
  - 5회차 확인 20번: 환불, 결제수단별 환불 순서, 결제 거래 원장의 환불 참조
  - 5회차 확인 19번: 배송유형코드에 EXCHANGE(교환 재배송)·RETURN(반품 회수) 추가
  - 3회차: 단품 재고 이력의 CANCEL·RETURN 변동
- 이번 회차에서 다루지 않는 것
  - 쿠폰 복원(어떤 쿠폰을 돌려줄지) → 쿠폰 회차
  - 적립금 잔액 원장(환원한 적립금이 어디에 쌓이는지) → 등급·적립금 회차
  - 판매자별 반품 배송비 정책 → 브랜드·판매자 회차
- 무신사 관찰
  - 마이페이지에서 주문상품별로 취소·반품·교환을 신청하고, 고객 변심 반품·교환은 배송비를 고객이 부담함 (💭 공개 화면과 업계 관행으로 추론)
  - 출고 전에는 바로 취소되고, 출고 후에는 반품으로 처리됨 (💭 추론)

### 클레임 설계의 핵심 질문
1. **취소·반품·교환을 한 엔티티로 담을까, 나눌까?** → 유형 1~4
2. **클레임 한 건은 어디까지 묶을까? 수량 일부는?** → 유형 5~9
3. **상태를 어디에 둘까?** → 유형 10~12
4. **누구 잘못인가? 배송비는 누가 내나?** → 유형 13~14
5. **얼마를, 어느 결제수단으로 돌려줄까?** → 유형 15~19
6. **반품·교환 배송비는 어떻게 받을까?** → 유형 20
7. **회수와 교환 재배송은?** → 유형 21~22
8. **교환한 단품은 어디에 기록할까?** → 유형 23~24

### 용어 정리 (이 문서에서)
| 용어 | 뜻 | 예시 |
|---|---|---|
| 클레임 | 취소·반품·교환 신청 한 건 | 판매자 B 데님 반품 |
| 클레임상품 | 클레임에 포함된 주문상품과 수량 | 티셔츠 블랙 M × 1 |
| 귀책 (PPT 외) | 클레임의 책임이 누구에게 있는가 | 고객 변심 = 고객, 불량·오배송 = 판매자 |
| 클레임 비용 | 고객 귀책 반품·교환 때 고객이 내는 배송비 | 반품 편도 3,000, 교환 왕복 5,000 |
| 회수 | 반품·교환 상품을 고객에게서 가져오는 배송 | |
| 검수 | 회수한 상품의 상태 확인 | 착용 흔적 → 불합격 |
| 환불 배분 | 환불 금액을 결제수단별로 나눈 것 | 적립금 417 + 카드 15,458 |

### 예시 주문 (4·5회차와 같은 주문)
```
판매자 A (무신사): 티셔츠 블랙 M × 2   상품금액 38,000   장바구니쿠폰 배분 1,251   적립금 배분 834
                   배송비 정책: 기본 2,500, 30,000원 이상 무료 → 배송비 0
판매자 B (데님랩): 데님 연청 30 × 1     상품금액 59,000   상품쿠폰 5,900 + 장바구니쿠폰 1,749   적립금 배분 1,166
                   배송비 정책: 기본 3,000, 70,000원 이상 무료 → 배송비 3,000

결제 (청구금액 91,100): 적립금 2,000 / 무신사머니 2,000 / 카드 87,100
```

| F. 클레임 비용 | 20. 차감 / 추가 결제 / 동봉 | 고객 부담 배송비를 어떻게 받나? |
| G. 회수·재배송 | 21. 배송 재사용형 → 22. 회수 엔티티 분리형 | 반품 회수는 어떤 배송인가? |
| H. 교환 | 23. 클레임상품 교환단품형 → 24. 교환 주문상품 생성형 | 바꾼 단품을 어디에? |

## A. 클레임 구조

### 1. 주문상품 컬럼형
**정의**: 주문상품(4회차)에 취소수량, 반품수량, 클레임사유, 클레임일시 컬럼을 둡니다.
- **단점**: 같은 주문상품에 클레임이 두 번(1개 취소 후 1개 반품) 생기면 담을 수 없습니다. 교환단품, 회수 배송, 검수 결과까지 넣으면 주문상품이 계속 커집니다. 4회차에서 "주문상품은 생성 후 수정하지 않는다"고 정한 원칙과도 맞지 않습니다.
- **무신사라면**: ❌

---

### 2. 클레임 통합 엔티티형
**정의**: 클레임(클레임유형코드 CANCEL / RETURN / EXCHANGE) + 클레임상품(주문상품, 수량)으로 나눕니다.
```
클레임 1 ──< M 클레임상품 >── 1 주문상품
```
| 클레임번호 | 유형 | 판매자 주문 | 클레임상품 |
|---|---|---|---|
| 1 | CANCEL | (81234, A) | 티셔츠 블랙 M × 1 |
| 2 | RETURN | (81234, B) | 데님 연청 30 × 1 |

- **장점**: 한 주문상품에 여러 클레임, 여러 주문상품을 묶은 클레임 모두 가능합니다. 세 유형의 흐름(신청 → 처리 → 완료)과 환불 계산이 거의 같아서 한 곳에서 다룹니다.
- **단점**: 교환단품, 회수 검수처럼 일부 유형에서만 쓰는 속성이 NULL로 남습니다.
- **무신사라면**: ✅

---

### 3. 슈퍼타입/서브타입형 (PPT: 슈퍼타입/서브타입 관계)
**정의**: 클레임(공통) 아래에 취소·반품·교환 서브타입을 1:1로 둡니다.
- **장점**: 유형별 속성이 자기 엔티티에만 들어갑니다.
- **판단**: 서브타입에만 있는 속성을 세어 보면 교환의 **교환단품**, 반품·교환의 **검수 결과** 정도입니다. 이마저 클레임상품 단위 속성이라 클레임 서브타입으로는 담을 수 없습니다. 5회차 결제 서브타입(카드사·할부, 은행·입금기한처럼 속성이 뚜렷이 다름)과 비교하면 나눌 이유가 약합니다.
- **무신사라면**: ❌ (2번 + 유형별 속성은 클레임상품의 선택 컬럼)

---

### 4. 유형별 독립 엔티티형
**정의**: 취소, 반품, 교환을 공통 부모 없이 각각의 엔티티로 둡니다.
- **단점**: "이 주문상품의 모든 클레임"을 보려면 세 엔티티를 합쳐야 하고(UNION), 환불·상태 이력·클레임상품 구조가 세 벌로 늘어납니다. 서브타입 기준 물리 테이블과 같은 문제입니다.
- **무신사라면**: ❌

---

## B. 클레임 단위

### 5. 주문 단위
**정의**: 한 주문에서 신청한 클레임을 주문 하나로 묶습니다.
- **단점**: 판매자 A·B 상품을 함께 반품하면 회수지·승인 주체·배송비 정책이 두 판매자로 나뉘는데 클레임 한 건에 섞입니다.

### 6. 판매자 주문 단위
**정의**: 클레임은 **판매자 주문(4회차) 하나**에 속합니다. 고객이 한 화면에서 A·B 상품을 함께 신청하면 클레임 2건으로 나눕니다.
- **장점**: 판매자의 승인·거부, 회수 배송, 배송비 재계산이 모두 판매자 주문 단위라 한 클레임 안에서 끝납니다.
- **무신사라면**: ✅

### 7. 주문상품 단위
**정의**: 클레임 한 건 = 주문상품 하나.
- **단점**: 같은 판매자의 티셔츠와 바지를 한 상자로 반품해도 클레임이 2건이 되어 회수 배송·배송비 차감이 나뉩니다.
- **무신사라면**: ❌

### 8. 주문상품 행 분할형
**정의**: 티셔츠 2개 중 1개를 취소하면 주문상품 행을 (수량 1, 정상) + (수량 1, 취소)로 나눕니다.
- **단점**: 주문 시점에 만든 주문상품과 할인 배분이 바뀌고, 그 주문상품을 참조하는 재고 이력·배송상품의 대상이 모호해집니다.
- **무신사라면**: ❌ (4회차 확인 10번에서 이미 제외)

### 9. 클레임상품 수량형
**정의**: 클레임상품에 수량을 두고, 주문상품은 그대로 둡니다. 남은 수량 = 주문 수량 − 완료된 취소·반품 수량 (파생).
- **무신사라면**: ✅

## C. 상태

### 10. 클레임 상태코드형
**정의**: 클레임에 상태를 둡니다.
```
취소: REQUESTED → COMPLETED                     (출고 전이면 바로 완료)
반품: REQUESTED → APPROVED → COLLECTING → COLLECTED → COMPLETED
교환: REQUESTED → APPROVED → COLLECTING → COLLECTED → RESHIPPING → COMPLETED
중단: REJECTED(판매자 거부·검수 불합격) / WITHDRAWN(고객 철회)
```
- **무신사라면**: ✅

### 11. 클레임상품별 상태형
**정의**: 클레임상품마다 상태를 둡니다.
- **판단**: 한 클레임의 상품은 같은 상자로 회수되고 함께 처리되므로 대부분 상태가 같습니다. 상품마다 다른 것은 **검수 결과**뿐이라 상태 대신 검수결과코드만 클레임상품에 둡니다.
- **무신사라면**: ❌ (검수결과코드만)

### 12. 상태 이력형 (점 이력)
**정의**: 고객·상품·주문상품과 같은 상태 이력 패턴. 거부·검수 불합격 사유가 여기에 남습니다.
- **무신사라면**: ✅

---

## D. 사유·귀책

### 13. 사유코드형
**정의**: 클레임사유를 코드로(CHANGE_OF_MIND 단순변심, SIZE 사이즈 불만, DEFECT 불량, WRONG_DELIVERY 오배송, DELAY 배송 지연, SOLD_OUT 판매자 품절) 두고, 상세 사유는 자유 입력으로 둡니다.
- **장점**: "사이즈 때문에 반품이 많은 상품" 같은 통계를 낼 수 있습니다 (리뷰 회차의 사이즈 추천과도 연결).
- **무신사라면**: ✅

### 14. 귀책 구분형
**정의**: 클레임에 귀책구분코드(CUSTOMER / SELLER)를 둡니다. 배송비를 누가 낼지가 귀책으로 정해집니다.

| 귀책 | 반품 배송비 | 원래 배송비 | 예 |
|---|---|---|---|
| CUSTOMER | 고객 부담 (편도, 무료배송이었으면 왕복) | 환불 안 함 | 단순변심, 사이즈 |
| SELLER | 판매자 부담 | 환불 | 불량, 오배송, 품절 |

- **사유코드에서 귀책을 계산하면 안 되나?** 사유는 고객이 고르지만 귀책은 판매자 확인 후 바뀔 수 있습니다 ("불량"으로 신청 → 검수 결과 단순변심). 그래서 사유와 별도로 **확정된 귀책**을 저장합니다 (파생 속성 아님).
- **무신사라면**: ✅

---

## E. 환불

### 15. 환불 계산형
**정의**: 환불 금액을 저장하지 않고, 클레임상품 × 주문상품 스냅샷(4회차)으로 매번 계산합니다.
- **단점**: 수량 일부 취소의 끝전, 배송비 재계산은 **클레임 시점의 판단**이 들어간 값입니다. 나중에 다시 계산하면 이후 클레임 때문에 결과가 달라질 수 있습니다 (예: 두 번째 취소가 첫 번째 취소의 배송비 재부과를 되돌림).
- **무신사라면**: ❌

### 16. 환불 금액 저장형
**정의**: 클레임 시점에 확정한 금액을 저장합니다.
- 클레임상품: **할인회수금액**, **적립금환원금액** (주문상품의 배분 금액 중 이번 수량 몫)
- 클레임: **배송비환불금액**, **배송비재부과금액**, **클레임비용**
- 상품금액(판매가 × 수량)은 스냅샷으로 언제든 같게 계산되므로 저장하지 않습니다 (파생).
- **무신사라면**: ✅ 정산·고객 문의의 근거가 되는 확정 값

### 17. 환불 엔티티 1:1 분리형
**정의**: 환불(클레임번호 PK, 금액들)을 클레임과 1:1로 분리합니다 (1회차 수직 분할형과 같은 판단).
- **판단**: 환불 금액이 없는 교환도 클레임비용·배송비 컬럼은 쓰고, 금액 컬럼은 0으로 두면 되어 NULL 문제가 작습니다. 분리하면 결제 거래(5회차)가 클레임과 환불 중 무엇을 참조할지 헷갈립니다.
- **무신사라면**: ❌ (금액은 클레임에)

### 18. 결제수단별 환불 배분형
**정의**: 클레임 환불액을 결제수단별로 나눈 **클레임 환불**(클레임번호 + 결제번호, 환불금액)을 둡니다. 실제 PG 취소는 5회차 결제 거래(CANCEL)이고, 그 거래가 어떤 클레임 환불인지 참조합니다.
```
클레임 ──< 클레임 환불 >── 결제
                │
                └──< 결제 거래(CANCEL)     FK = (클레임번호, 결제번호) 복합
```
- **복합 FK의 효과**: 결제 거래는 이미 결제번호를 가지고 있습니다. (클레임번호, 결제번호)를 함께 FK로 걸면 **"이 취소 거래의 결제 = 이 환불 배분의 결제"** 를 키가 보장합니다. 4·5회차에서 인조 식별자 때문에 업무 규칙으로 넘겼던 "같은 부모 소속 확인"을, 이번에는 복합 FK로 키에 맡기는 사례입니다.
- **환불 순서 (추천)**: ① 적립금은 클레임상품의 적립금환원금액만큼 적립금으로 ② 나머지는 외부 결제(카드·간편결제·가상계좌)를 먼저 ③ 외부 결제 잔액이 모자라면 무신사머니
- **무신사라면**: ✅

### 19. 배분 금액 비례 회수형 (4회차 안분의 반대)
**정의**: 수량 일부를 취소하면 주문상품의 할인·적립금 배분액을 **수량 비율**로 돌려받습니다.
```
회수액 = floor(배분액 × 클레임수량 / 주문수량)
단, 그 주문상품의 마지막 남은 수량이면 회수액 = 배분액 − 이미 회수한 합계 (잔액 전액)
```
| 예: 티셔츠 2개 | 장바구니쿠폰 배분 1,251 | 적립금 배분 834 |
|---|---|---|
| 1개 취소 | floor(1,251 / 2) = 625 | 417 |
| 나머지 1개 취소 | 1,251 − 625 = **626** | 834 − 417 = 417 |

- 마지막 수량에서 잔액 전액을 돌려주므로, 모두 취소하면 회수 합계가 배분액과 정확히 같아집니다 (끝전 누락 없음).
- **무신사라면**: ✅

## F. 클레임 비용

### 20. 고객 부담 배송비를 받는 방법
| 변형 | 방법 | 장점 | 단점 |
|---|---|---|---|
| 20-a. 환불에서 차감 | 환불액 − 반품 배송비 | 별도 결제 없음 | 교환처럼 **환불이 없으면** 쓸 수 없음 |
| 20-b. 추가 결제 | 클레임 신청 때 배송비 결제 | 교환에도 사용 | 결제 흐름이 하나 더 생김 |
| 20-c. 동봉 | 상자에 현금 동봉 | 시스템 단순 | 확인 불가, 분실 |

- **무신사라면**: ✅ **반품은 20-a 차감, 교환은 20-b 추가 결제**. 클레임에 클레임비용처리코드(DEDUCT / PAY / NONE)를 둠
- **5회차 결제와의 연결**: 추가 결제도 결제(5회차) 한 행입니다. 실패 후 재시도로 결제가 여러 행이 될 수 있으므로, FK는 클레임이 아니라 **결제 쪽에 클레임번호**로 둡니다 (1:M의 FK는 M 쪽에).

## G. 회수·재배송

### 21. 배송 재사용형
**정의**: 반품 회수와 교환 재배송도 5회차 배송(`shipment`) 한 행으로 두고, 배송유형코드(RETURN / EXCHANGE)와 클레임번호로 구분합니다.
- **장점**: 송장, 택배사 추적 이력, 배송상품 구조를 그대로 씁니다. 5회차에서 배송유형코드를 미리 둔 이유입니다.
- **방향**: 회수 배송은 고객 → 판매자로 방향만 반대입니다. 배송상품의 주문상품은 "어떤 주문상품을 회수하나"를 뜻합니다.
- **무신사라면**: ✅

### 22. 회수 엔티티 분리형
**정의**: 회수(회수 송장, 회수지, 회수일시)를 별도 엔티티로 둡니다.
- **단점**: 송장·추적 이력 구조가 배송과 중복됩니다.
- **무신사라면**: ❌

- **무신사라면**: ❌

### 3-3. 관계 도출 및 정의

|---|---|---|---|---|---|

| 클레임 ↔ 결제 | M:N → 클레임 환불 | 1:M, 1:M | | **식별** | PK = 클레임번호 + 결제번호 |
| 클레임 환불 → 결제 거래 | 기본 | 1:M | 선택-선택 | 비식별 | FK = (클레임번호, 결제번호) 복합. CANCEL 거래만 |
| 클레임 → 결제 | 기본 | 1:M | 선택-선택 | 비식별 | 클레임 비용 추가 결제 (재시도 포함) |
| 클레임 → 배송 | 기본 | 1:M | 선택-선택 | 비식별 | 회수(RETURN)·교환 재배송(EXCHANGE) |
| 클레임 → 클레임 상태 이력 | 기본 | 1:M | 필수-필수 | 비식별 | |

**관계도**
```
[판매자 주문] ─< [클레임] ─< [클레임상품] >─ [주문상품]
                   │  │            └──○ [단품] (교환단품)
                   │  ├─< [클레임 상태 이력]
                   │  ├─< [클레임 환불] >─ [결제]
                   │  │        └─< [결제 거래] (CANCEL, 복합 FK)
                   │  ├─< [결제] (클레임 비용 추가 결제)
                   │  └─< [배송] (회수·교환 재배송)
```

**식별자 선택 포인트**
- **클레임 = 인조 식별자**: 클레임상품·환불·상태 이력·결제·배송이 모두 참조합니다. 판매자 주문에서 상속하면 (주문번호 + 판매자번호 + 순번) 3개 속성이 됩니다.
- **클레임상품 = 식별 관계 (클레임번호 + 주문상품번호)**: "한 클레임에 같은 주문상품은 한 줄"을 키가 보장합니다.
- **클레임 환불 = 식별 관계 (클레임번호 + 결제번호)**: "한 클레임에서 결제 한 건당 환불 배분은 한 줄"을 키가 보장하고, 결제 거래가 이 키를 복합 FK로 참조합니다.
- 여전히 키로 보장되지 않는 것: 클레임상품의 주문상품이 **그 클레임의 판매자 주문에 속하는지** (주문상품이 인조 식별자라서). 업무 규칙으로 관리합니다.

### 3-4. 테이블 정의

**표기**
- 도메인: 번호, 명, 코드, 여부(Y/N), 일시, 금액, 숫자
- NULL: N = 필수, Y = 선택
- 키: PK(기본 키), FK(참조 키), AK(대체 식별자). 같은 번호(①)는 함께 묶인 복합키
- 모든 테이블 마지막에 시스템 컬럼 4개(`created_by`, `created_at`, `updated_by`, `updated_at`)를 둡니다. 아래 표에서는 생략했습니다.

**시나리오별 금액 검산** (예시 주문 기준, 각 시나리오는 독립)

**S1. 출고 전 티셔츠 1개 취소 (고객 변심)**
| 항목 | 금액 | 근거 |
|---|---|---|
| 상품환불금액 | 19,000 | 19,000 × 1 (파생) |
| 할인회수금액 | −625 | floor(1,251 × 1/2) |
| 배송비재부과금액 | −2,500 | 남은 판매자 A 상품금액 19,000 < 무료배송기준 30,000 |
| **환불총액** | **15,875** | |
| 클레임 환불 | 적립금 417 + 카드 15,458 | 적립금환원금액 floor(834 × 1/2) = 417, 나머지는 외부 결제 먼저 |

**S1-2. 이어서 나머지 티셔츠 1개도 출고 전 취소**
| 항목 | 금액 | 근거 |
|---|---|---|
| 상품환불금액 | 19,000 | |
| 할인회수금액 | −626 | 마지막 수량 → 1,251 − 625 (잔액 전액) |
| 배송비환불금액 | +2,500 | 판매자 A 상품이 하나도 출고되지 않았으므로 S1에서 재부과한 배송비를 돌려줌 |
| **환불총액** | **20,874** | 적립금 417 + 카드 20,457 |
| 검산 | S1 + S1-2 = 36,749 | 판매자 A 몫 (38,000 − 1,251) ✅ |

**S2. 데님 반품 (배송 후, 고객 변심)**
| 항목 | 금액 | 근거 |
|---|---|---|
| 상품환불금액 | 59,000 | |
| 할인회수금액 | −7,649 | 상품쿠폰 5,900 + 장바구니쿠폰 1,749 (수량 1 → 전액) |
| 배송비환불금액 | 0 | 고객 귀책, 이미 배송됨 |
| 클레임비용 (DEDUCT) | −3,000 | 반품 편도 배송비 |
| **환불총액** | **48,351** | 적립금 1,166 + 카드 47,185 |

**S2-2. 같은 데님을 불량으로 반품 (판매자 귀책)**
| 항목 | 금액 |
|---|---|
| 상품환불금액 − 할인회수금액 | 51,351 |
| 배송비환불금액 | +3,000 |
| 클레임비용 | 0 (판매자 부담) |
| **환불총액** | **54,351** = 적립금 1,166 + 카드 53,185 (5회차 시나리오 4의 카드 부분취소 53,185와 같음) |

**S3. 출고 전 전체 취소 (판매자 A·B 클레임 2건)**
| 클레임 | 환불총액 | 클레임 환불 |
|---|---|---|
| A | 38,000 − 1,251 = 36,749 | 적립금 834 + 카드 35,915 |
| B | 59,000 − 7,649 + 배송비 3,000 = 54,351 | 적립금 1,166 + 카드 51,185 + 무신사머니 2,000 |
| 합계 | **91,100 = 청구금액** ✅ | 적립금 2,000 / 카드 87,100 / 머니 2,000 = 결제 3건 전액 ✅ |

**S4. 티셔츠 1개 M → L 교환 (고객 변심)**
| 엔티티 | 내용 |
|---|---|
| 클레임 | EXCHANGE, 귀책 CUSTOMER, 클레임비용 5,000(왕복), 처리 PAY |
| 클레임상품 | 티셔츠 블랙 M × 1, 교환단품 = 티셔츠 블랙 L, 할인회수·적립금환원 0 |
| 결제 | 카드 5,000 (클레임번호 있음) → 승인 후 진행 |
| 배송 | RETURN 1건(M 회수), EXCHANGE 1건(L 발송), 모두 클레임번호 있음 |
| 단품 재고 이력 | L −1 (EXCHANGE, 교환 승인 시), M +1 (RETURN, 검수 통과 시) |

**제약 조건 (PPT 4가지)**
| 제약 | 적용 |
|---|---|
| 키 제약조건 | 모든 PK |
| 실체 무결성 | PK와 필수 속성 NOT NULL |
| 영역 무결성 | 수량 ≥ 1, 금액 ≥ 0, 환불금액 > 0, 유형·상태·사유·귀책 코드값 |
| 참조 무결성 | 모든 FK. 클레임 → 판매자 주문, 결제 거래 → 클레임 환불은 복합 FK |

**키 구조로 보장되지 않는 규칙 (업무 규칙)**
| 규칙 | 이유 |
|---|---|
| 클레임상품의 주문상품은 그 클레임의 판매자 주문에 속해야 한다 | 주문상품이 인조 식별자라서 |
| 주문상품별로 진행 중·완료된 클레임 수량 합계(철회·거부, 검수 FAIL 제외) ≤ 주문 수량 | 여러 행 합계 |
| 주문상품당 진행 중인 클레임은 하나다 | 조건부 유일 |
| CANCEL은 출고되지 않은 수량만, RETURN·EXCHANGE는 배송완료된 수량만 신청할 수 있다 | 배송상품(5회차)과 비교 |
| 할인회수금액·적립금환원금액 = floor(배분액 × 클레임수량 / 주문수량), 마지막 남은 수량이면 잔액 전액 | 계산 규칙 (19번) |
| 배송비환불·재부과는 클레임 후 남은 판매자 주문 상품금액과 배송비 정책 스냅샷(4회차)으로 정한다. 귀책 SELLER면 고객 부담 배송비가 없다 | 계산 규칙 |
| 클레임 환불 합계 = 클레임 환불총액(파생) | 여러 행 합계 |
| 클레임 환불의 적립금(POINT) 결제 금액 = 클레임상품 적립금환원금액 합계 | 의도적 중복 |
| 환불 배분은 적립금 → 외부 결제 → 무신사머니 순서이고, 결제마다 환불금액 ≤ 결제 잔액 | 계산 규칙 (18번) |
| 클레임 환불별 결제 거래(CANCEL, SUCCESS) 합계 = 환불금액이 되면 클레임을 COMPLETED로 바꾼다 | 여러 행 합계 |
| 클레임비용처리코드가 PAY면 클레임번호가 있는 결제가 APPROVED여야 승인할 수 있다 | 다른 엔티티 상태 |
| 회수·재배송 배송의 판매자 주문 = 클레임의 판매자 주문 | 배송과 클레임이 판매자 주문을 각각 참조 |
| 교환단품은 같은 상품의 다른 단품이고, 판매중이며 재고가 있어야 한다. 옵션추가금액이 다르면 교환할 수 없다 | 단품·상품 비교 (확인 15번) |
| 재고: 취소 완료 시 CANCEL(+), 반품 검수 통과 시 RETURN(+), 교환 승인 시 교환단품 EXCHANGE(−) | 3회차 재고 이력 연결 |
| 클레임이 완료되어 주문상품의 남은 수량이 0이 되면 주문상품을 CANCELED·RETURNED로 바꾼다. 취소와 반품이 섞이면 **마지막에 완료된 클레임 유형**을 따른다 | 4회차 확인 10번 (확인 21번) |
| 클레임 비용 추가 결제(클레임번호가 있는 결제)의 주문 = 클레임의 주문 | 결제와 클레임이 주문을 각각 참조 (확인 14번 보완) |
| 환불 배분 대상 결제는 **클레임번호가 없는** 주문 결제다 | 클레임 비용 결제는 환불 대상이 아님 (확인 14번 보완) |
| 환불총액은 0 이상이어야 한다. 배송비 재부과·클레임비용(DEDUCT)이 상품 환불액보다 크면 신청할 수 없다 | 파생 값 범위 (확인 8번 보완) |
| 결제 거래의 클레임번호는 클레임 환불로 생긴 CANCEL 거래에만 채운다. 교환 철회·거부로 클레임 비용 결제를 취소할 때는 클레임번호 없이 일반 취소로 남긴다 (결제의 클레임번호로 추적) | 거래 유형별 참조 (확인 11번 보완) |
| 검수 FAIL인 클레임상품은 할인회수·적립금환원금액을 0으로 확정하고 환불에서 뺀다. 모두 FAIL이면 클레임을 REJECTED로 바꾼다 | 부분 불합격 (확인 6번 보완) |
| 교환 클레임이 철회·거부되면 승인 때 차감한 교환단품 재고를 되돌린다 (EXCHANGE, +) | 3회차 재고 이력 연결 (확인 18번 보완) |

> 📌 이번 회차의 학습 포인트: **파생 속성처럼 보여도, 계산에 "그 시점의 판단"이 들어가면 저장합니다.** 환불 금액은 수량 비례 끝전과 배송비 재계산이 클레임 순서에 따라 달라지므로 확정 값으로 남깁니다. 반대로 상품환불금액(판매가 × 수량)은 언제 계산해도 같으므로 저장하지 않습니다.

## 5. 업무 규칙과 다음 회차로 넘긴 항목

### 키 구조만으로는 보장되지 않는 업무 규칙
3-5의 "키 구조로 보장되지 않는 규칙" 21개에 더해:
- 클레임 귀책을 바꾸면 클레임비용과 배송비 조정 금액을 다시 계산한다 (환불 배분 확정 전까지만)
- 환불 배분을 확정한 뒤에는 클레임상품·금액 컬럼을 수정하지 않는다
- 구매확정(4회차 CONFIRMED)된 주문상품에는 반품·교환을 신청할 수 없다

### 다음 회차로 넘긴 항목
- 쿠폰 복원, 할인 유형별 회수 내역 → 쿠폰 회차
- 적립금 환원 원장, 구매확정 전 적립 예정 적립금 회수 → 등급·적립금 회차
- 판매자별 반품 배송비·반품지 정책 → 브랜드·판매자 회차
- 검수 불합격 상품 재발송, 반품 기한(배송완료 후 7일 등) → 운영 정책
- 클레임 사유 통계와 사이즈 추천 연결 → 리뷰 회차
